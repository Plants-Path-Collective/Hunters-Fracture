Consola de desarrollo

Consola en pantalla para inspeccionar el juego, ejecutar utilidades y probar sistemas durante el desarrollo.

Disponibilidad y uso

DevConsole se crea automáticamente al iniciar el juego en el Editor y en las Development Builds. No requiere añadir un objeto a una escena. La consola no se incluye en builds de producción.

  • Pulsa F4 con la vista Game enfocada para abrir o cerrar la consola.
  • Escribe un comando y pulsa Enter. Los nombres de comandos no distinguen mayúsculas de minúsculas; se acepta una barra inicial opcional.
  • Usa Tab para autocompletar, ↑/↓ para recorrer el historial y Page Up/Page Down para desplazarte por los logs.
  • Las comillas dobles agrupan argumentos con espacios, por ejemplo: scene "Overworld Scene".

Mientras está abierta, la consola bloquea los mapas de entrada de gameplay y muestra el cursor. Al cerrarla restaura el mapa previo.

Comandos incluidos

Escribe help para ver los comandos registrados y help <comando> para consultar la firma y descripción de uno. Algunas utilidades generales:

ComandoDescripción
clearLimpia las líneas visibles.
echo <texto...>Imprime texto en la consola.
timescale [scale]Muestra o cambia Time.timeScale; 0 pausa el tiempo.
scenesLista las escenas de Build Settings y las cargadas actualmente.
scene <nombre|índice> [additive]Carga una escena; se puede indicar si la carga es aditiva.
console.saveGuarda el historial de logs en Application.persistentDataPath.
quitSale del juego o detiene Play Mode en el Editor.

También hay comandos de prueba agrupados por prefijo, como combat.*, party.*, enemy.* y challenge.*. Consulta help para ver la lista vigente.

Añadir comandos

  1. Crea o reutiliza una clase estática en el código del sistema correspondiente; por ejemplo, Assets/Scripts/97_DevTools/GameCommands.cs.
  2. Marca un método estático con [ConsoleCommand("nombre", "Descripción para help")].
  3. Usa únicamente los tipos de parámetros admitidos y devuelve string para mostrar un resultado o void si no hace falta imprimirlo.
using DevTools;

internal static class DebugCommands
{
    [ConsoleCommand("dev.greet", "Saluda al nombre indicado.")]
    private static string Greet(string name = "developer") =>
        $"Hello, {name}!";
}

La consola descubre por reflexión métodos estáticos públicos o privados marcados con el atributo al arrancar. No es necesario registrarlos manualmente. El nombre es único y no distingue mayúsculas de minúsculas; usa puntos para agrupar comandos relacionados.

Para un comando de juego real, llama desde el método a la API pública del sistema correspondiente, comprueba que ese sistema esté disponible y devuelve un mensaje claro si no se puede realizar la operación.

Parámetros admitidos

  • string, int, long, float, double, bool y cualquier enum.
  • Los parámetros opcionales de C# se muestran entre corchetes en la ayuda y usan su valor predeterminado si se omiten.
  • params string[] puede usarse como último parámetro para aceptar una cantidad variable de palabras.
  • Los argumentos se pasan en orden. Los valores booleanos aceptan true/false, 1/0, on/off y yes/no; los números usan punto decimal.

Compilación y recomendaciones

  • Envuelve las clases de comandos en #if UNITY_EDITOR || DEVELOPMENT_BUILD para excluirlas de builds de producción.
  • Los comandos descubiertos solo por reflexión deben marcarse con [Preserve] en su clase para evitar que IL2CPP los elimine en Development Builds.
  • Valida los argumentos y el estado del juego antes de modificarlo. Devuelve mensajes claros en caso de no poder ejecutar la operación.
  • Prueba el comando con help <comando> y verifica tanto los valores válidos como los inválidos.
