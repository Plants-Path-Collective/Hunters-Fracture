03 · SISTEMA

Sistema de Desafíos

Desafíos definidos con ScriptableObjects: escuchan eventos de progreso, entregan recompensas al completarse y guardan el progreso y los desbloqueos entre sesiones.

Arquitectura

ChallengeManager es un Singleton persistente que recibe un ChallengeCatalog, carga el archivo de guardado y conecta las condiciones de cada desafío que aún no está completado. Las condiciones escuchan el hub estático ChallengeEvents; los sistemas de gameplay informan estadísticas o hitos sin depender directamente del manager.

ChallengeCatalog Asset que enumera las definiciones disponibles y permite buscarlas por challengeID. Se asigna al manager; no es un Singleton.
ChallengeSO Definición de un desafío: ID estable, nombre y descripción localizados, icono, visibilidad, condición, alcance y recompensas. El progreso no se guarda en este asset.
ChallengeConditionSO Condición reutilizable que se suscribe a eventos y entrega al manager un callback para sumar progreso. Cada condición devuelve una acción de limpieza para desuscribirse al completar.
ChallengeManager Mantiene progreso y desbloqueos en memoria, anuncia cambios, concede recompensas y coordina la persistencia.

Condiciones y alcance

Hay dos tipos de condición implementados:

  • StatThresholdConditionSO suma una cantidad de una estadística hasta alcanzar un objetivo. El enum contempla estadísticas como enemigos derrotados, combates ganados, daño infligido e ítems recogidos; no todas tienen un emisor conectado actualmente.
  • MilestoneConditionSO suma una unidad cuando se informa un ID de hito concreto. Puede requerir más de una notificación del mismo hito.

El alcance Lifetime conserva el progreso entre runs. PerRun reinicia el progreso incompleto cuando otro sistema llama a ChallengeManager.BeginRun(); los desafíos ya completados siguen completados. El sistema no inicia una run automáticamente.

Progreso que se reporta actualmente

CombatChallengeReporter informa enemigos derrotados (una vez por unidad), daño aliado solicitado —incluye overkill—, combates ganados y huidas. Aunque CHALLENGE_STAT también declara ItemsCollected, RunsStarted y RunsCompleted, no encontré emisores de gameplay para esos valores. Tampoco encontré llamadas de gameplay a ReportMilestone; el harness de depuración sí permite probar estadísticas e hitos manualmente.

Completar y conceder recompensas

Al alcanzar el objetivo, el manager marca el desafío completado, se desuscribe de su condición, concede las recompensas configuradas, emite OnChallengeCompleted y guarda. Las recompensas actuales permiten añadir una clave de desbloqueo genérica, desbloquear un ítem o desbloquear una unidad.

  • Ítems: las claves usan item:{itemID}. ItemCatalog.IsAvailable permite los ítems normales y filtra del pool los marcados lockedByDefault hasta que se desbloquean.
  • Unidades: las claves usan unit:{unitID}. PartyRecruiter sincroniza las unidades desbloqueadas al iniciar y después de completar un desafío; añade al grupo las que estén en su lista de reclutables y aún no estén presentes.

El campo hidden indica que una interfaz debe ocultar el nombre y la descripción hasta completar el desafío. El manager expone catálogo, progreso y eventos para una UI, pero no encontré un componente de pantalla de desafíos entre los scripts actuales.

Persistencia

JsonChallengeSaveBackend guarda challenges.json en Application.persistentDataPath. El JSON contiene la versión del formato, el progreso por ID (valor y estado completado) y las claves de desbloqueo. Para escribir, usa un archivo temporal y después lo reemplaza o mueve al destino. Si no puede leer un archivo existente, registra el error e intenta conservar una copia con extensión .corrupt.

Se guarda al completar un desafío, al terminar un combate cuando hay cambios, cuando BeginRun() reinicia progreso y al salir de la aplicación si quedan cambios pendientes. El progreso también puede consultarse con GetProgress e IsCompleted; los desbloqueos, con IsUnlocked.

Eventos y API

ElementoUso
ChallengeEvents.ReportStat(stat, amount)Reporta un incremento positivo de una estadística.
ChallengeEvents.ReportMilestone(id)Reporta un hito identificado por una cadena no vacía.
OnProgressChangedEvento del manager con desafío, progreso actual y objetivo.
OnChallengeCompletedEvento del manager al completar un desafío; lo usa PartyRecruiter.

Los reportes no hacen nada si no hay suscriptores. Para validar el sistema en Play Mode, ChallengeDebugHarness permite reportar estadísticas e hitos desde el menú de contexto del componente.
